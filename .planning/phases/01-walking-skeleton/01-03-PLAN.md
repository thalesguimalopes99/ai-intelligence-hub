<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feed content → Actions shell | Collector output flows into the commit step |
| Fork PRs → CI | Untrusted code runs in ci.yml |
| GITHUB_TOKEN (contents: write) → repo | Bot can push to main |
| Repo secret VERCEL_DEPLOY_HOOK → network | Only if fallback activated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-07 | Elevation (script injection) | collect.yml run: blocks | mitigate | All dynamic values passed via env:, never ${{ }} in run: (test-enforced); commit message uses only date + digit-validated ITEMS_NEW; HOLD digit-validated and capped at 600 |
| T-01-08 | Elevation | ci.yml on fork PRs | mitigate | `pull_request` (never `_target`), permissions contents: read, no secrets referenced (test-enforced) |
| T-01-09 | Tampering | Concurrent runs / lost commits | mitigate | concurrency group collect without cancel, checkout ref main, rebase-retry push, no force push (test-enforced) |
| T-01-10 | Information disclosure | VERCEL_DEPLOY_HOOK | mitigate | Secret exposed only as step-level env of the hook step, never echoed (curl output to /dev/null), not available to npm ci |
| T-01-11 | Spoofing | Commit identity | accept | Owner noreply identity is public by design and required by Vercel Hobby (D-10) |
</threat_model>
