# Feature Research

**Domain:** Public AI-news aggregator / intelligence hub (static site, rule-based, PT-BR UI, English content)
**Researched:** 2026-10-06
**Confidence:** MEDIUM. Competitor feature sets come from product docs and secondary write-ups. SEO and accessibility rules come from official Google, Next.js and WCAG sources, so those parts are HIGH.

## Reference Products (what the ecosystem looks like)

| Product | Model | Features that matter to us |
|---------|-------|----------------------------|
| **Techmeme** | Algorithm plus about 26 human editors. One shared front page. | It **clusters** one story with its follow-up coverage ("More:" links from other outlets plus social and HN/Reddit threads). Ranking uses link count and age, with anti-gaming for bursts of links. **River** is a pure reverse-chronological view. There is a leaderboard of sources. The front page is the same for everyone, by design. Editors rewrite headlines (we cannot, since we have no editors and no LLM). |
| **Hacker News** | Community votes, time-decayed. | Dense text list. Source **domain shown next to the title**. Relative age ("3 hours ago"). **/front?day=** "past" archive by date. No images, extremely fast. |
| **daily.dev** | Personalised dev-news feed (needs an account). | Filters by **tags/sources**. "Most upvoted" defaults to **last 7 days** with a timeframe switch. A "Best discussions" feed. Card grid. Personalisation needs login, which we must not copy. |
| **TLDR AI** | Daily email digest. | Short one-line blurbs, sections by theme, one issue per day. Its value is "the day in 5 minutes". It is already one of our sources. |
| **smol.ai AI News / Latent Space** | LLM-written daily recaps. | Recaps generated by paid LLMs, which we cannot do. A "what happened today" framing is still possible without an LLM. |
| **Feedly / RSS readers** | Personal reader. | Unread state, saved items, mute keywords. These need accounts or local storage. |
| **Indie AI aggregators** (best-ai.news, aiaggregator, Horizon) | Rule-based or with an LLM. | **Cross-source clustering by title similarity** (Jaccard ≥ 0.5 plus union-find). **"Breaking" = 3+ sources within 4h**. 0–100 quality score (source tier, recency, depth). Regex entity matching for model and company names. Entity pages for SEO. Support for reduced motion. |

**Takeaways:**
1. Every serious aggregator clusters the same story across sources. This is the main thing that separates an aggregator from a plain merged RSS feed.
2. Techmeme and HN show that a fast, dense, text-first list beats image-heavy cards for the "first tab of the day" use case.
3. Personalisation in this category needs accounts, which are out of scope. Techmeme proves that "everyone sees the same page" is a valid, even respected, choice.
4. Google's spam policy treats "reproducing content feeds from other sites without providing some type of unique benefit" as scraped spam. For SEO, the hub's own added value (clustering, score, categories, curation pages) has to be visible in the HTML.

## Feature Landscape

### Table Stakes (Users Expect These)

Users leave if these are missing.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| **Reverse-chronological feed (River)** | Base layer of every aggregator (Techmeme River, HN /newest). | LOW | Group by day with PT-BR headers ("Hoje", "Ontem", "seg., 5 de out."). Show the first ~50 items in static HTML and load more on the client ("Carregar mais"). Do not ship the full 30-day `items.json` up front. |
| **Card shows title, source, company, relative time, primary category, outbound link** | HN shows domain plus age. Users judge trust by source first. | LOW | The title links **directly to the original URL**, which is the core value. Use `<time datetime="ISO">` and render relative time on the client ("há 2 h" via `Intl.RelativeTimeFormat('pt-BR')`) to avoid stale "há 5 min" in static HTML and hydration mismatch. Open in the same tab by default. Readers expect the back button to return to the hub, so add no `target=_blank` unless the user asks for it. |
| **Short excerpt (trimmed, plain text)** | TLDR and Techmeme give one or two lines of context. | LOW | Limit to about 200–280 characters. Strip HTML and tracking. Copyright rules mean no full text. |
| **Same-story clustering across sources** ("+3 fontes") | Without it, a GPT/Claude launch shows up 6 times and the feed feels broken. Every competitor does this. | MEDIUM | The collector clusters by canonical URL plus title similarity. The UI shows one primary card (prefer the official lab source, otherwise the highest source weight) with an expandable list of the other sources, each with its own link. Depends on dedup in the collector. |
| **Filters: company, category, period** | daily.dev tags/sources and every reader have these. | MEDIUM | Use chips. On mobile, put them in a horizontally scrolling chip row plus a bottom sheet for the full set. **Reflect filters in the URL** so they can be shared and the back button works. "Limpar filtros" clears them. Show the result count. |
| **Text search over the current window** | Power users try Ctrl+F or a search box first ("did anything about Gemini come out?"). | LOW–MEDIUM | Client-side search over `items.json` (title, source, company, categories). A normalised substring match is enough for v1, and a small index such as MiniSearch can come later. **Not in PROJECT.md Active, so add it as a requirement.** |
| **Freshness signal: "Atualizado há X min" plus LIVE / Atrasado** | A feed that might be stale is not trusted. HN and Techmeme feel live because they always are. | LOW | Compute from `meta.json.lastUpdated` vs `Date.now()` **on the client**, never at build time. The 90-min threshold covers GitHub cron delays of 5–30 min. Poll `meta.json` every ~5 min with `cache: 'no-store'`. When new data has been deployed, show a "N novidades — atualizar" pill. **Never reorder the list under the user's finger.** |
| **Highlights (Destaques)** | Techmeme's top-of-page and TLDR's lead item. Users want "what matters" before "everything". | MEDIUM | Big launches from major labs in the last 48h, ranked by score. Cap at about 3–6 items. Needs a launch-detection rule (model-name regex plus verbs such as "introducing/launch/release/available") and the source weight. If none qualify, show the top-scored items rather than an empty section. |
| **Trending / "Em alta" (multi-source)** | Techmeme's core signal is "many outlets are covering this". best-ai.news uses "3+ sources within 4h". | MEDIUM | Derive from cluster size: ≥3 distinct sources (or ≥2 non-Reddit/non-aggregator sources) within 24h. Show "N fontes". Depends on clustering. |
| **Top of the week** | daily.dev "Most upvoted, last 7 days" pattern. | LOW | Top 10 **clusters** (not items) by score over 7 days. Precompute in the collector. |
| **Archive / history** | HN "past". People look for "that thing from last month". | LOW–MEDIUM | `/historico` → `/historico/2026-09`, with day grouping and the same filters. Monthly JSON is lazy-loaded. Generate pages statically for SEO. |
| **Copy / share button** | Content-creator use case (pautas). Mobile users share to WhatsApp. | LOW | `navigator.share` when available (mobile), otherwise `navigator.clipboard.writeText`. Text format: `Título — Fonte\nURL`. Show "Copiado!" feedback announced through `aria-live`. Both APIs need HTTPS, which Vercel provides. |
| **Source transparency** (which sources, health, limitations) | Trust. The project's Core Value. | LOW–MEDIUM | `/fontes` status page: ok / erro / last success, item count, method (RSS/API/scraping), known limitations (Reddit unstable, The Batch absent). A small footer link from the LIVE badge. |
| **Mobile-first, fast, dark** | Most "first tab of the day" reading happens on phones. | MEDIUM | Single-column cards. Tap targets at least 24×24 CSS px (WCAG 2.2 2.5.8, AA), with 44px recommended. No layout shift. No third-party images (see anti-features). Target LCP under 2.5s on 4G. Keep the theme dark, but meet contrast requirements (below). |
| **Basic SEO: title/description, canonical, OG/Twitter cards, sitemap.xml, robots.txt** | A public site nobody can find, or that unfurls badly in WhatsApp or LinkedIn, loses its main growth channel. | LOW | Next.js Metadata API (`generateMetadata`), `app/sitemap.ts`, `app/robots.ts`. OG images are generated in code with `next/og` `ImageResponse`, which meets the "no AI images" constraint. `<html lang="pt-BR">`. Full details below. |
| **Accessibility baseline (WCAG 2.2 AA)** | Legal and ethical baseline, and also good for SEO. | LOW–MEDIUM | See the accessibility checklist below. |
| **Empty / error / loading states in PT-BR** | Filters with zero results, or a missing monthly archive, must not look broken. | LOW | "Nenhuma notícia com esses filtros" plus a clear-filters button. Skeletons only during client fetches. |

### Differentiators (Competitive Advantage)

None of these are expected, but they fit the Core Value (reliable, transparent, self-updating) and the owner's use cases (pautas, tool decisions).

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **Explainable score ("Por que 82?")** | Rule-based scoring is a weakness if hidden and a strength if shown. Nobody else explains their ranking. | LOW–MEDIUM | The collector stores a `scoreBreakdown` array (for example `+25 fonte oficial`, `+15 nome de modelo`, `+10 3 fontes`, `−8 idade`). The UI shows it in a popover or `<details>`. This makes rules easy to tune and builds trust. **Store the breakdown from day one.** Adding it later means reprocessing. |
| **Official-source-first clustering** | When OpenAI announces something, the primary link is openai.com and not a rewrite. Techmeme credits originals, and we can do it automatically. | LOW (given clustering) | Rule: lab-official > research > newsletters > community. |
| **"Novo desde sua última visita"** (no account) | Feedly-style unread value without login. Fits the "first tab of the day" use. | LOW | `localStorage.lastVisit`. Add a "NOVO" badge and a divider line "— visto até aqui —". Local only. No sync, by design. |
| **Multi-select "Copiar pauta"** | The owner makes content. Selecting 5 items and copying a formatted list (Markdown/WhatsApp) is a very specific workflow nobody serves. | LOW–MEDIUM | Selection mode with checkboxes, a sticky bottom bar "Copiar N itens", and a format toggle (texto / Markdown). Local state only. |
| **The hub's own RSS/Atom output** (global, Destaques, per category) | Lets power users follow the hub's curated and deduplicated output in their own reader or Slack. Few aggregators of this kind do this, and it costs almost nothing. | LOW | Next.js route handlers (`app/feed.xml/route.ts`, `app/categoria/[slug]/feed.xml/route.ts`), statically generated. Link with `<link rel="alternate" type="application/rss+xml">`. Each entry links to the original source (not to us), with "via AI Intelligence Hub" in the description. |
| **Public JSON "API"** | The data files are already public in the repo and on Vercel. Documenting `/data/items.json` turns that into a developer feature. | LOW | Send CORS headers via `vercel.json` and document the schema in the README. |
| **Indexable landing pages per category and company** (`/categoria/agents`, `/empresa/anthropic`) | This is where the SEO value is. "notícias Anthropic" or "novidades agentes IA" in PT-BR is low-competition. It is also how the site avoids the "scraped feed" label: each page is a curated, categorised and ranked view. | MEDIUM | Static pages for 13 categories and about 12 companies, with a unique PT-BR intro paragraph (hand-written, 2–3 sentences) for each. Canonical URLs are path-based. Filter combinations in query parameters are `noindex` or canonicalise to the base page. |
| **Daily digest page "Resumo do dia"** (`/dia/2026-10-06`) | TLDR-like "the day in 5 min", built from rules (top N clusters of the day by category). It also produces a durable, indexable, date-stamped page. | MEDIUM | Generated from the archive. No LLM summary, just a structured list. A strong v1.x candidate. |
| **Model/entity tags** (GPT-5, Claude, Gemini, Llama…) | Lets people track a model across labs and sources. best-ai.news uses 195 regexes for this. Directly serves "decidir ferramentas". | MEDIUM | Uses the same regex dictionary as the score's "nome de modelo" boost, so the work is reused. Entity pages can wait until v1.x. |
| **Source-health transparency, publicly visible** | Rare. Most aggregators fail silently. Saying "Reddit bloqueado desde 14h" builds credibility. | LOW (data already in `meta.json`) | A small health dot on the LIVE badge (for example "18/20 fontes ok"). |
| **Keyboard navigation (j/k, o, c, /)** | HN and Feedly power users love it. Cheap. | LOW | `j/k` move focus, `o` open, `c` copy, `/` focus search, `?` help. It must not interfere with screen readers: only active when focus is not in an input, and documented. |
| **Correct language tagging** (`lang="en"` on English titles in a `pt-BR` page) | Screen readers pronounce English headlines correctly, and it helps SEO language signals. Rarely done. | LOW | Default `lang="en"` on the title/excerpt element, unless the source language is known to be different. |

### Anti-Features (Do NOT Build)

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| **Per-article pages on our domain that host the excerpt and send users "through" us** | "More pages = more SEO." | Thin or scraped content under Google's spam policy. Copyright risk. Adds a click between the user and the source, which goes against the Core Value of the correct link to the original. | Link directly to the source. Put the SEO effort into category, company, day and archive pages that add curation value. |
| **`NewsArticle` / `Article` JSON-LD for third-party items** | Rich results. | We are not the publisher. Marking up other people's articles as our own breaks the structured-data guidelines, and NewsArticle needs images/publisher data we do not own. | Use `WebSite` (+ `SearchAction` if search is URL-addressable), `CollectionPage` and `ItemList` whose `url` points to the originals, plus `BreadcrumbList`. |
| **Thumbnails / og:image hotlinked from sources** | Cards "look richer". | Each card hits third-party servers (privacy, slow, broken images, CLS), adds copyright exposure and another scraping step per item. HN and Techmeme prove text-first wins for this use. | Use a coded **source monogram/logo badge** (SVG/CSS, consistent with the "no AI images" constraint) and a category colour plus icon. |
| **Auto-refresh that inserts items into the visible list** | "Real-time feel". | The list jumps while reading, users lose their place, and screen readers get spammed. | A "N novidades" pill that the user taps to apply. LIVE stays a passive indicator. |
| **Infinite scroll with no URL state** | Modern feel. | Breaks the back button, footer access and sharing. Keyboard and assistive-tech users get trapped. | "Carregar mais" button plus day grouping. Optionally a `?ate=2026-10-01` cursor. |
| **Comments, upvotes, reactions** | daily.dev and HN have them. | Need accounts, a backend and moderation, all out of scope. Votes without identity are trivially gamed. | Multi-source coverage ("N fontes") is the hub's own popularity signal. |
| **Personalised algorithmic feed / "For you"** | daily.dev does it. | Needs accounts or tracking. Techmeme shows that a shared front page builds trust. Opaque. | URL filters plus local "favorite categories" in localStorage (v1.x at most). |
| **AI summaries, chatbot, "ask the news"** | Every 2025–26 AI aggregator has one. | Explicitly out of scope (no chatbot, no paid APIs). Hallucination risk on a trust-focused product. | Show the original excerpt and the score breakdown. Free open-source translation or summaries in the Action can be evaluated in v2. |
| **Auto-translated headlines in v1** | PT-BR audience. | Deferred in PROJECT.md. Free machine-translation quality on model names and jargon is poor ("Claude Sonnet" gets translated). | Keep the PT-BR UI and English content. Add `lang="en"` tagging. |
| **Email newsletter / web push notifications** | Retention. | Need an email service provider or a push backend plus consent management (LGPD). Not static. | The hub's own RSS (and RSS-to-email services users can pick themselves). |
| **Pulsing/animated "LIVE" that stays green when data is stale** | Looks alive. | Lies about freshness, which damages trust. Motion is an accessibility problem. | The LIVE state is computed from real `lastUpdated`. The pulse animation is disabled under `prefers-reduced-motion`. When stale, switch honestly to an amber "Atrasado — última coleta há 3 h". |
| **Showing raw `score: 73` on every card with no meaning** | "Data-driven" look. | Meaningless numbers make it look arbitrary. | Show a 3-level relevance chip (Alta / Média / Baixa), with the number and breakdown in the "Por que?" popover. |
| **Too many overlapping highlight sections** (Destaques + Em alta + Top semana + feed, all on the home page) | Every idea seems useful. | The same GPT launch appears 4 times above the fold, which feels as broken as having no dedup at all. | Home page: Destaques (up to 4) plus feed, with "Em alta" as a badge on cards and a tab. Top da semana gets its own route or tab. Exclude items already shown in Destaques from the "Em alta" strip. |
| **Unbounded arXiv firehose in the main feed** | "Complete coverage". | About 400 items a day drown the labs. | Cap it and score it. HF Daily Papers is the curated signal. Optionally a separate "Research" tab. |

```
    └──required by──> [/historico pages] ──> [Resumo do dia /dia/... (v1.x)] [sitemap entries]

    └──required by──> [Shareable filtered views] [Back-button correctness] [Path-based SEO landing pages]

    ├──required by──> [SEO: HTML contains the feed, OG, sitemap, RSS output]
    └──conflicts──> [Build-time relative timestamps / LIVE state]  (must be computed client-side)

```

### Dependency Notes

- **Clustering comes before any trending/highlight UI.** "Em alta", "Top da semana" and "+N fontes" are all views over clusters. If the collector stores loose items without a `clusterId`/`sources[]`, these features have to be retrofitted. The JSON schema must include cluster data in Phase 1.
- **`scoreBreakdown` must be stored when the score is computed.** It is cheap to add then and expensive to add later, and it is the main tool for tuning ranking rules after launch.
- **SSG and freshness pull against each other.** Pages are rebuilt on each data commit (about hourly), but anything time-relative (LIVE, "há X min", NOVO) has to be computed in the browser from ISO timestamps. Otherwise the HTML lies between deploys, and React hydration warnings appear.
- **The entity dictionary is shared** by the classifier, the score boost, launch detection (Destaques) and entity tags. Keep it as one module or file (for example `rules/entities.ts`) so the rules stay consistent.
- **SEO landing pages depend on the URL design.** Single-dimension filters as path routes (`/categoria/[slug]`, `/empresa/[slug]`) are indexable. Combinations go in query parameters on the client and are `noindex` or canonicalised. Decide this before building the filter UI.

## SEO Checklist (public static site)

| Item | How | Confidence |
|------|-----|------------|
| Per-page `<title>` and meta description in PT-BR | Next.js `metadata` / `generateMetadata`. | HIGH |
| Canonical URLs | `alternates.canonical`. Filter-combination query URLs canonicalise to the base path. | HIGH |
| Open Graph + Twitter card | `openGraph`, `twitter` in metadata. Coded OG image via `app/opengraph-image.tsx` (`next/og` ImageResponse) per route type. Vital for WhatsApp/LinkedIn unfurls. | HIGH |
| `sitemap.xml` | `app/sitemap.ts` (Next 16 docs, verified). Include home, /categoria/*, /empresa/*, /historico/*, /top-semana, /fontes. `lastModified` = `meta.lastUpdated`. | HIGH |
| `robots.txt` | `app/robots.ts`, pointing to the sitemap. | HIGH |
| The hub's RSS output | Route handlers that return `application/rss+xml`, plus a `<link rel="alternate">` in the head. | HIGH |
| Content in the initial HTML | The feed is rendered at build time (SSG), not client-only. Google requires SEO-critical content to be present before JS runs. | HIGH |
| Structured data | `WebSite`, `CollectionPage` + `ItemList`, `BreadcrumbList`. **Not** `NewsArticle` for third-party items. | MEDIUM (policy interpretation) |
| Unique added value per indexable page | Short PT-BR intro, category stats, cluster and score info. This is a defence against "scraped content" classification. | MEDIUM |
| `*.vercel.app` domain | Indexable but weaker. A custom domain later requires 301s and a canonical update. Use a single `SITE_URL` env var from day one. | MEDIUM |

## Accessibility Checklist (WCAG 2.2 AA)

- Dark theme contrast: body text ≥ 4.5:1, UI components and focus rings ≥ 3:1. Muted grey metadata on near-black is the usual failure, so check it.
- Categories must not be shown by **colour only**. Use a label or icon as well.
- A visible focus indicator on every card link, chip and button. Add a "Pular para o feed" skip link.
- Filter chips are real `<button aria-pressed>` elements or a checkbox group, so they work with the keyboard.
- The bottom sheet or modal traps focus correctly and closes with Esc.
- Copy feedback and "N novidades" use `aria-live="polite"`. Do **not** make the whole feed a live region.
- `<html lang="pt-BR">` plus `lang="en"` on English titles and excerpts.
- `prefers-reduced-motion` disables the LIVE pulse and skeleton shimmer.
- Tap targets ≥ 24×24 px (2.5.8), with 44 px aimed for on primary actions.
- Each card is an `<article>` with a heading (`h2`/`h3`) so screen-reader users can jump by heading. Relative times are wrapped in `<time datetime>`.
- The outbound link text is the headline. Avoid many identical "Abrir fonte" links, or give each one a distinct `aria-label` ("Abrir na fonte: {título}").

## MVP Definition

### Launch With (v1)

- [ ] Chronological feed with day grouping and direct outbound links: the core value
- [ ] Cards with source, company, client-side relative time, primary category and relevance chip
- [ ] Cross-source clustering shown as "+N fontes": without it the feed looks broken on launch days
- [ ] Filters (company, category, period) synced to the URL, plus simple text search
- [ ] Destaques (48h big launches, capped) and "Em alta" badge/tab
- [ ] LIVE/Atrasado, computed on the client, plus a non-disruptive "N novidades" pill
- [ ] Status page `/fontes` with per-source health
- [ ] Copy/share (Web Share → clipboard fallback)
- [ ] Top da semana (by cluster)
- [ ] Archive by month
- [ ] SEO baseline: metadata, canonical, coded OG images, sitemap, robots, the hub's RSS output
- [ ] Explainable score popover. The data is needed anyway for tuning, and the UI is cheap.
- [ ] WCAG 2.2 AA baseline, mobile-first, dark

### Add After Validation (v1.x)

- [ ] Path-based landing pages `/categoria/*` and `/empresa/*` with intros and per-category RSS: once the base feed is stable, this is the SEO growth lever
- [ ] "Novo desde sua última visita" (localStorage): when the owner uses the hub daily
- [ ] Multi-select "Copiar pauta": when the content-creation workflow starts
- [ ] Model/entity tags and entity pages: once the entity regex dictionary has matured
- [ ] Daily digest `/dia/AAAA-MM-DD`
- [ ] Keyboard shortcuts
- [ ] Documented public JSON endpoint with CORS

### Future Consideration (v2+)

- [ ] Free headline translation (open-source model in the Action): quality risk on jargon
- [ ] Local "favorite categories" / muted keywords (localStorage)
- [ ] The Batch via headless Playwright
- [ ] Custom domain (plan for the 301 and canonical move)
